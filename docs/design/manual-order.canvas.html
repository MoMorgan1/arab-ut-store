Manual order — inside the orders page

Slice G1. A manual order is what makes track.arab-ut.com deletable: the tracker can hold an order the store never sold, and until the store can create one too, the old site cannot be switched off.

Owner decision, 2026-09-13: it lives inside the orders page, not on a screen of its own — same list, same filters, one place to control from. The store already has a pattern for exactly that: the coupons screen creates and edits through a Sheet drawer opened from its toolbar, with twenty-odd fields in it (admin-coupon-drawer.tsx). This extends that vocabulary rather than inventing a second one.

Owner decision, 2026-09-13: cashback and loyalty are earned on a bank-transfer manual order and not on a gift. Real money in, real rewards out. The form says so where the choice is made, not in a footnote.

Admin is English-only (owner decision, 2026-08-21). The phone artboard leads, at 390px, and every screen below is the real compiled stylesheet — not a mockup of it.

1 · Where it starts

One primary action on the orders toolbar. Nothing else about the list changes, and no new navigation item appears.

2 · The drawer, phone first

One drawer, four groups, and a footer that stays put. The type of order is the first decision because it changes what the rest of the form asks for — the money group and the fulfillment group are both branches of it.

3 · The same drawer at desktop width

The Sheet primitive caps itself at sm:max-w-sm — 384 pixels — so the coupon drawer is a narrow column on a 1440 screen as well. That is fine for coupons. It is the one place this form may have to differ, and it is a question for you below.

4 · What this costs behind the screen

It reuses checkout, it does not copy it

PlaceOrder writes the order, the items, the credentials and the number. The admin skill forbids an admin-only duplicate of checkout, and a second checkout is how two code paths start disagreeing about price.

New values it needs:

  • orders.channel gains manual (today: store, salla_import)
  • a payment provider for a bank transfer (today: wallet, paylink)
  • an admin permission of its own, so creating orders is not implied by viewing them

One feature, not two

You asked for a manual order and for a bare supplier link. They are the same screen, because fulfillment_jobs.order_item_id is NOT NULL: a link pointing at a supplier order with no store order has nowhere to live.

Making that column nullable would produce order-less jobs floating free — which is exactly the split that let the tracker drift away from the store in the first place.

Cashback, as decided

A bank transfer earns cashback and loyalty; a gift earns neither. The completion effects already fire exactly once per order from reconciliation, so this is a condition on one branch and not a second reward path.

The form states it at the point of choice, so nobody has to remember the rule.

Audit, and what never reaches it

Every creation is a staff audit record: who, when, the customer, the items, the money and the delivery choice.

The EA password and backup codes are not in it, not in the page payload, not in a URL and not in a log line. They are stored encrypted on the item the way checkout stores them, and read back only through the existing reveal path with a fresh password confirmation.

Needs your answer

  • Drawer width on desktop. Keep the 384px column the coupon drawer uses, or widen this one to 672px for the two-column layout above? The phone is identical either way.
  • Can a manual order use wallet balance? A customer with balance might reasonably pay that way, but it is a third money path on this form and I would leave it out of the first version.
  • Who may create one? Admin only, or support staff too? It creates money records, so my recommendation is admin only to start.

What I did not do, and why

A separate /admin/orders/new page. It was my first instinct for a form this long, and it is the wrong call here: the store already creates a twenty-field coupon in a drawer from its list screen, so a page would be a second way to do the same thing. Your reading was right — same list, same place.

A multi-step wizard. Steps are for a sequence a person cannot see the end of. This form is four groups you can scroll, and a wizard would hide the total behind a Next button.

A new navigation item. A manual order is an order. It belongs in the orders list, marked by its channel, and nowhere else.
