# Objective

Describe one bounded implementation task and its intended outcome.

# Allowed paths

- List every file or directory the implementer may change.

# Non-goals

- List adjacent work, refactors, and decisions that must remain untouched.
- Never include passwords, tokens, private keys, or other secrets in this brief.

# Acceptance criteria

- State observable behavior that proves the task is complete.
- Include edge cases the implementation must preserve.

# Required checks

- List the exact targeted test, lint, typecheck, or build commands to run.
- Require the final report to include changed files, check outcomes, deviations, and risks.
